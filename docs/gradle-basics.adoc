** Configure the `compileJava` task
+
[source,kotlin]
----
import org.gradle.api.tasks.compile.JavaCompile

plugins {
    `java-library`
}

tasks.named<JavaCompile>("compileJava"){
    this.options.compilerArgs.add("-parameters")
}
----
+
*** This tells the Java compiler to store method parameter names in the generated .class files
*** To find existing options enter **JavaCompile** into the search

** Talk about versions in Gradle
*** `2.5.252` : Requests 2.5.252. A higher version can be selected during dependency conflict resolution.
*** `2.5.+` : Dynamically selects the latest available 2.5.x version, unless conflict resolution selects a higher version.
*** `2.5.252!!` : Strictly requires version 2.5.252.
*** `version { strictly("[2.5, 2.6[") prefer("2.5.252") }` : Gradle may use a version `>= 2.5 & < 2.6`. If `2.5.252` is available it is the preferred version.

** Create `./build.gradle.kts`
+
[source,kotlin]
----
import com.github.benmanes.gradle.versions.updates.DependencyUpdatesTask

tasks.withType<DependencyUpdatesTask>().configureEach {
    revision = "release"
    rejectPreReleases = true
    checkForGradleUpdate = true
    gradleReleaseChannel = "current"
}
----
+
*** Show only stable Gradle updates (`checkForGradleUpdate = true` & `gradleReleaseChannel = "current"`)
*** Show only non-pre-releases (`revision = "release"` & `rejectPreReleases = true`)
*** `tasks.named...` configures the specific tasks identified by its name
*** `tasks.withType...` configures all tasks with the given type
*** `.configureEach` : registers a configuration action that executes when a matching task is realized
*** `.all` : eagerly realizes and configures matching tasks, including tasks that might not be needed for the requested build

** Refactor to write the greeting into a file
+
[source,kotlin]
----
import org.gradle.api.file.RegularFileProperty
import org.gradle.api.tasks.OutputFile

abstract class SayHello : DefaultTask() {

    @get:Input
    var myName: String = "Florian"

    @get:OutputFile
    abstract val greetingFile: RegularFileProperty
----
+
<<<
+
[source,kotlin]
----
    @TaskAction
    fun greet() {
        val greeting = "Hello $myName"
        val output = greetingFile.get().asFile

        output.parentFile.mkdirs()
        output.writeText(greeting)

        println(greeting)
    }
}

tasks.register<SayHello>("sayHello") {
    group = "Custom"
    description = "Writes a personal greeting to a file"

    greetingFile.set(
        layout.buildDirectory.file("greeting.txt")
    )
}
----
+

** Explain Properties
*** Attendees should look at `val output = greetingFile.get().asFile` and `greetingFile.set(`
*** `greetingFile` is a Property
*** A Gradle `Property<T>` is a container for a value of type `T`.
*** Properties support lazy evaluation (a value does not have to be calculated or retrieved when it is configured)
** Explain build phases
*** Gradle executes a build in three phases **Initialization**, **Configuration** and **Execution**
*** In **Initialization** Gradle reads `settings.gradle.kts`, Determines the root project and its subprojects, Configures build-level settings such as plugin and dependency repositories
*** In **Configuration** Gradle evaluates the relevant `build.gradle.kts` files, Registers and configures tasks, Determines the task graph for the requested execution
*** In **Execution** Gradle executes the required task actions, Tasks can be skipped if they are `UP-TO-DATE`, Tasks are executed according to their dependencies
** Demonstrate the phases
*** Run `./gradlew help --info`
+
<<<
+
** Back to the last example
*** In **Configuration** phase the task type and the `tasks.register` is evaluated
*** The `greetingFile` is access in this phase but it does not exist yet
*** The property works a some kind of container for the file
*** In **Execution** phase the `greetingFile` property is accessed via its `get()` method.
*** At this point in time the property get evaluated (the file exists)
** The layout helper provides access to Gradle-managed project locations, such as `projectDirectory` and `buildDirectory`
